# PAARAL Student View — Build Workflow

## Overview

Feature-chunk build plan for the student-facing enrollment portal mockup.
Scope: NCR + Region III + Region IV-A (50 synthetic schools).

Each chunk is independently confirmable. Status tracked per chunk.

---

## Chunk 1: Project Scaffolding ✅

**Goal:** Working React app with map, school list, and filter sidebar.

**Decisions made:**
- Vite + React 19, Tailwind CSS v4, Lucide React
- No router: single-page mockup
- No state library: useState/useMemo sufficient
- Single `App.jsx`: all components inline for mockup speed
- 50 synthetic schools inline in `schools` array (real names, synthetic numerics)
- SVG-based Carto Light map (`PhilippinesMap`)

**Artifacts:**
- `src/App.jsx` — full app
- `src/index.css` — Tailwind directives
- `src/main.jsx` — React root
- `public/assets/` — ecair-logo.png, deped-logo.png

## Chunk 2: Student Portal — LRN Verification ✅

**Goal:** Right sidebar portal with LRN identity check against DepEd LIS.

**Key decisions:**
- LRN verification = registry identity check only. Not an ESC eligibility gate.
- Mock uses hardcoded valid LRN set (not a prefix trick like `startsWith("1")`)
- Success message: "LRN confirmed in the DepEd Learner Information System (LIS)"
- 800ms simulated network delay for realism

**Demo LRNs:**
| LRN | Behavior |
|---|---|
| `100000000001` | Valid, fresh (no draft) |
| `100000000002` | Valid, with 3 draft choices |
| `200000000001` | Invalid |

**Draft choices flow:**
- LRN `100000000002` returns 3 pre-saved choices (Bagumbayan NHS, St. Mary's Academy, Pasig Grace Christian School)
- Student sees "You already have choices on record" summary with Load Draft / Start fresh
- "Load Draft" populates wishlist and navigates to My Choices tab

## Chunk 3: Student Portal — Tabbed Structure ✅

**Goal:** Reorganize the right sidebar into four tabs to prevent crowding as features are added.

**Tab structure:**
| Tab | Contents |
|---|---|
| Verify | LRN check + draft detection |
| Eligibility | ESC category questionnaire + document checklist |
| My Choices | School wishlist (editable) |
| Survey | Pilot feedback + Submit button |

**Key decisions:**
- Submit button lives exclusively in the Survey tab
- Survey completion is a gate for submission (required, not optional)
- Eligibility tab is informational — does not gate any other step
- Tabs are freely navigable (no enforced sequence)

## Chunk 4: ESC Eligibility Questionnaire ✅

**Goal:** Branching questionnaire that places a learner in ESC Category A/B/C/D and outputs a tailored document checklist.

**Policy source:** E-GASTPE 2026 Revised Guidelines — Article III, Sections 7–10.

**Question flow:**

```
Q1: How did you complete Grade 6?
  → public  → Q2 (SEG check)
  → private → Q3 (income)
  → als     → Q3 (income)

Q2: Social Equity Group membership? (multi-select)
  → any SEG selected → result (Category A)
  → none             → Q3 (income)

Q3: Monthly household income? (PIDS classification)
  → poor / low / lower_middle / middle → Q4 (employment)
  → above                              → result (ineligible)

Q4: Parent/guardian employment status?
  → any → result (Category B / C / D)
```

**Category determination:**
| Path | Category |
|---|---|
| public + any SEG | A |
| public + no SEG + eligible income | B |
| als + eligible income | C |
| private + eligible income | D |
| any + above income (no SEG) | null (ineligible) |

**Income brackets (PIDS, user-provided 2026-05-04):**
- Poor: < ₱10,957
- Low income: ₱10,957 – ₱21,194
- Lower middle class: ₱21,194 – ₱43,828
- Middle class: ₱43,828 – ₱76,669
- Above (ineligible for B/C/D): > ₱76,669

**Document list** generated by `getDocList(category, answers)` — pure function, module-level.

**Navigation:** Back button at every step. "Start over" resets to schoolType step.

**Validation note shown in result:** ESC School Committee makes the final determination. This is self-assessment only.

## Chunk 5: Pilot Survey ✅

**Goal:** Collect pilot feedback from students before they submit. Survey completion unlocks the Submit button.

**Required questions (3):**
1. Ease of use — 1–5 scale
2. Did information help you decide? — Yes / Somewhat / No
3. Biggest concern about enrolling — Cost / Distance / Quality / Slot availability

**Optional:**
4. Open text suggestions

**Pre-submit checklist shown in Survey tab:**
- LRN verified
- School choices added
- Public JHS included as backup
- Survey complete

**`canSubmit` gate:** `wishlist.length > 0 && hasPublicAlternative && lrnVerified === 'valid' && surveyComplete`

## Chunk 7: Modal-Based Account Creation ✅

**Goal:** Students browse schools freely as guests. Account creation (LRN + ESC eligibility) happens in a modal overlay, not in the right panel.

**Key decisions:**
- Modal triggered by: "Create Account to Apply" CTA in guest panel, or "Add to My Choices" when not authenticated
- Modal steps: Step 1 LRN verify → optional draft detection → Step 2 ESC eligibility → result → "Create My Account" CTA
- `account` state (null | { lrn, category, answers }) replaces `lrnVerified === 'valid'` as the auth gate for canSubmit
- `pendingSchool` auto-added to wishlist on account creation if triggered from "Add to My Choices"
- Guest right panel: selected school mini card + CTA, or welcome CTA if nothing selected
- Authenticated right panel: 2 tabs only (My Choices + Survey); LRN + ESC category badge in header
- Modal closes on X or backdrop click; state preserved across open/close
